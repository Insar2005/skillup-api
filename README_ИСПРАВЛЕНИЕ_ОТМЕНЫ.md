# SkillUp API v29.5.2 — восстановление отменённого расхода

Это **точечное дополнение** существующего Railway API v29.5/29.5.1, а не новая серверная ветка.

## Что исправлено

- Кнопка «↶ Отменить» сохраняет исходную операцию в `finance_action_history` в одной PostgreSQL-транзакции с её исключением из активных финансов.
- Сразу после отмены появляется «↷ Вернуть».
- Текстовое «Верни» / «Восстанови» после отмены вызывает именно серверный обработчик, а не Claude. Поддерживается из Telegram-бота и Mini App.
- При восстановлении возвращаются исходная сумма, валюта, категория, примечание, дата и `externalId`; не создаётся новая копия.
- Повторное нажатие, повторная доставка Telegram update и попытка восстановить чужую операцию не должны создавать дубликаты.
- Отмены и восстановления, сделанные через Telegram-бота, появляются в истории одного чата SkillUp.
- Ответы об успехе строятся по факту записи в БД, а не по тексту модели.

## Установка

1. Перед деплоем создай резервную копию существующей PostgreSQL и сохрани рабочий коммит API.
2. В **существующий** репозиторий `skillup-api` добавь/замени именно эти файлы:
   - `src/ai-finance.js`
   - `src/bot.js`
   - `src/ai-routes.js`
   - `sql/005_finance_action_history.sql` **(новый файл)**
3. Файл `src/ai.js`, поправленный в v29.5.1, **не трогай**: его инструкция Claude остаётся прежней.
4. Commit → Push → Deploy в действующем сервисе Railway `skillup-api`.
5. Проверь, что в Deploy Logs появилось `Applied migration: 005_finance_action_history.sql` и затем `Database ready`. Если миграция уже применена, повторной строки не будет.
6. Отправь боту «Купил самсу за 80 сомов». Должен появиться короткий ответ о записи.
7. Нажми «↶ Отменить» → бот должен ответить «Отменил операцию» и показать «↷ Вернуть».
8. Нажми «↷ Вернуть» либо напиши «Верни» → бот должен ответить «Восстановил операцию: −80 KGS ...».
9. Проверь в Mini App, что расход вернулся **ровно один раз**. Попробуй повторно нажать старую кнопку «Вернуть»: двойной записи быть не должно.

## Ограничения

- Операция, отменённая **до установки** этого патча, восстановлению не подлежит через новый журнал: старая версия физически удаляла её, не сохраняя снимок. Такой расход нужно добавить заново.
- Короткая команда «Верни» восстанавливает последнюю одиночную отменённую операцию **за последние 24 часа**. Более старые записи не восстанавливаются одной неоднозначной командой.
- Восстановление *пакетов по фотографиям чеков* этим патчем пока не реализовано: у чеков отдельная логика отмены.
- Это локально протестированный патч. Реальная миграция и работа Telegram callback в production проверяются после твоего Deploy.
- Никаких секретов в ZIP нет. Существующие переменные Railway, PostgreSQL и UI не менять.
