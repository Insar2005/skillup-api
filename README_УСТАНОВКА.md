## Зачем

У Telegram-бота и Mini App теперь один серверный маршрут для **ясных** команд: `dispatchSkillUpAction`. Он последовательно проверяет корректные команды изменений, удаления/восстановления целей, восстановления финансов и добавления финансовых операций. При выполнении получает результат от PostgreSQL, а не выдумывает подтверждение через Claude. Если команда не распознана, она уходит в Claude для совета и уточнения. Данные разных пользователей не смешиваются; все операции используют существующие user-scoped функции.

- Расход «393 сом за доставку резисторов» теперь определяется как 393 KGS, категория «Доставка».
- Вопрос «393 сом за доставку резисторов?» **не** создаёт расход.
- Claude получает уточнение в системном контексте, что сервер **может** записывать финансы и изменять цели. Модель не должна называть подтверждённые сервером операции «выдуманными».
- Обычные действия остаются без подтверждений; защищённое массовое удаление использует прежнюю функцию `handleDevelopmentText` с кнопками в Telegram.

## Проверка

На тестовом Telegram аккаунте:
1. `393 сом за доставку резисторов` → короткое подтверждение `393 KGS · Доставка`; проверить PostgreSQL/Финансы.
2. `393 сом за доставку резисторов?` → вопрос, **без** записи.
3. `Переименуй цель ...` → результат в «Развитие» после обновления с сервера.
4. `Отмени последнее изменение` → откат только если история и версия документа позволяют.
5. `Удали все тестовые цели` → проверить, что сервер **не** удаляет массово без подтверждения.
6. После действия спросить Claude `Ты записывал расход?` → не должен отрицать подтверждённый результат; при неясности нужно сверять БД.
7. Проверить `GET /health`, чат через Mini App, голос, фото чека, права другого пользователя.

## Границы этого этапа

Это **ещё не полный tool-calling агент**. Claude получает read-only инструменты отчёта и списка целей, а действия исполняет общий серверный маршрутизатор до вызова модели. Неоднозначные команды пока могут требовать переформулирования. Напоминания и динамический вызов мутирующих инструментов моделью входят в следующий этап. Специального read-tool для точной сверки финансов внутри Claude пока нет: модель не должна утверждать, что проверила БД, если этого не было.

**Локальные проверки:** 28 тестов целевых модулей прошли. Продукционный Railway с этим патчем не проверен; нужен тест на существующей ветке.
