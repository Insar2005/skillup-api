# SkillUp v29.5.3 — умные категории и управление целями

Точечное обновление **существующего** SkillUp API v29.5.2 на Railway. Не создавайте новый сервис и не сбрасывайте PostgreSQL.

## Перед установкой

1. Создайте резервную копию PostgreSQL и сохраните работающий коммит API.
2. Убедитесь, что API уже использует ветку v29.5.2 с `finance_action_history` и авторизацией Telegram.
3. Сравните заменяемые файлы с текущим репозиторием, если после v29.5.2 вы что-то правили вручную.

## Файлы API

Скопируйте из архива в корень **существующего** `skillup-api`:

- `src/development-actions.js` — новый обработчик удаления/восстановления целей;
- `src/category.js` — новая смысловая классификация расходов;
- `src/ai-finance.js` — правила и категории;
- `src/ai-routes.js` — прямые команды из Mini App;
- `src/bot.js` — прямые команды из Telegram и кнопки;
- `src/ai.js` — обновлённая системная инструкция Claude;
- `sql/006_development_actions.sql` — миграция. Не удаляет существующие данные.

Остальные файлы и переменные не меняйте. После Commit/Push и успешного Railway Deploy в логах при первом применении миграции появится `Applied migration: 006_development_actions.sql`. Если миграция уже была применена, эта строка не повторяется.

## Переменные Railway

- `ANTHROPIC_API_KEY` и `ANTHROPIC_MODEL` остаются прежними.
- Необязательно: `CATEGORY_WEB_SEARCH=true` — разрешить **один** веб-поиск Claude для нераспознанного товара. По умолчанию выключено: классификация работает по правилам и при необходимости через Claude без веб-поиска. Веб-поиск увеличивает задержку и может тарифицироваться отдельно.

При запросе Claude о категории сервер отправляет только укороченное описание покупки (без числовой суммы/телефонов), а не весь финансовый документ. Возвращённая моделью категория проверяется по фиксированному разрешённому списку. При ошибке модели используется «Прочее».

## Фронтенд

Если используете SkillUp v29.5, в его GitHub-репозитории замените **только** `skillup-ai.js` из второго архива. Эта правка вызывает уже существующий `window.skillupCloudRefresh()` после удаления/восстановления из ИИ. Дизайн, `index.html`, `skillup-cloud.js`, Dockerfile не меняются.

После удалений через отдельный Telegram-бот приложение увидит новые данные при перезапуске или по кнопке «Профиль → Синхронизация → Обновить с сервера». Если на устройстве есть несохранённые локальные изменения, облачный мост правильно остановит загрузку — не затирайте конфликт вслепую.

## Тесты после Deploy

1. Telegram: «Купил чай за 100 рублей» → `Продукты`, RUB.
2. Telegram: «Выпил чай в кафе за 150 сомов» → `Еда вне дома`, KGS.
3. Telegram: «Купил старлинк за 1000$» → `Электроника`, USD.
4. Telegram: «Оплатил Starlink за 50$» → `Связь и интернет`, USD.
5. Mini App или Telegram: «Удали цель Relax» → одна цель удалена, остальные не затронуты.
6. «Верни удалённые цели» → возвращается цель вместе с этапами и прошлой историей.
7. «Удали мои цели, они были для теста» → бот покажет список и **одно** подтверждение; до него ничего не удаляется.
8. Кнопка «Удалить N целей» → удаляются только те цели, которые были перечислены при запросе; навыки и привычки остаются.
9. Перезапустите Mini App, проверьте цель/расход и ревизию облачного документа.

## Ограничения

- Подтверждение остаётся для **массового** удаления, для удаления одной однозначно названной цели не нужно.
- При совпадении названий нескольких целей удаление по имени не производится. Нужна идентификация.
- Архив целей хранится 30 дней (восстановление проверяется по дате); автоматическое физическое удаление архивных строк этим пакетом не настроено.
- Модуль сейчас удаляет только цели (`goal`), а не направления, навыки и привычки.
- В расходах по-прежнему нет FX-конвертации: KGS/USD не прибавляются к рублёвому балансу. Старый интерфейс группирует новые категории, не входящие в его кольцевую диаграмму, в сектор «Прочее», хотя индивидуальная операция сохраняет выбранную категорию.
- Веб-поиск использует Anthropic `web_search`, а не Google Search; включается только как опция для неизвестных покупок.
- Проверены синтаксис и unit tests, но PostgreSQL в реальном Railway, API Claude и Telegram callbacks нужно проверить после установки.
