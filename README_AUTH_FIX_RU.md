# SkillUp API v0.2.1 — исправление и диагностика HTTP 401

Источник: предыдущая API-ветка v0.2.0 из текущей переписки, **не отдельный новый сервер**.

## Изменения

- В проверке подписанного Telegram initData по токену бота исключается `hash`, но учитывается `signature`, если Telegram её передал. Это соответствует документации Telegram для HMAC через токен бота (не путать с Ed25519 third-party).
- Дополнительная валидация `auth_date`, включая отсутствие поля.
- При `AUTH_DIAGNOSTICS=true` Railway Logs показывает только код причины отклонения (`hash_mismatch`, `init_data_missing`, `auth_date_expired`, `signed_user_invalid_or_missing` и др.) и факт наличия `signature`. **Никакого вывода полного initData, user ID, hash, токенов и приватной переписки**.
- Все прежние маршруты и SQL-таблицы сохранены. Никаких новых миграций, очистки, импорта данных или ИИ.

## Перед деплоем

1. Убедись, что твой развернутый Railway API соответствует предыдущему `src/server.js` (v0.2.0). Если за это время появились твои правки, не перезаписывай их — сначала сравни diff.
2. Создай резервную копию GitHub-ветки/тега.
3. Замени файлы в **существующем** репозитории `skillup-api`. Приложение SkillUp v29 не менять.
4. В `skillup-api → Variables` временно добавь `AUTH_DIAGNOSTICS=true`; секреты оставь в Railway.
5. Убедись, что в логах и GET `/` версия стала `0.2.1-authfix`. Запусти Mini App через Telegram и открой проверку пяти нажатиями в шапке.
6. Если 200 — мы перешли к следующему этапу. Если 401 — в Railway `skillup-api → Deployments → View Logs` найди `[Telegram Auth] rejected=...` и сообщи только **причину** и `signature_present`, без секретов.
7. После диагностики выключи `AUTH_DIAGNOSTICS` или установи `false`.

## Возможные причины

- `hash_mismatch` с исправленным кодом: проверь совпадение `TELEGRAM_BOT_TOKEN` и бота запуска Mini App; также исключи изменения исходной initData.
- `init_data_missing`: API не получил `X-Telegram-Init-Data` в том запросе.
- `auth_date_expired`: полностью перезапусти Mini App.
- `signed_user_invalid_or_missing`: подпись действительна, но в initData отсутствует подходящий user.
- `Service not configured` / 503: отсутствует токен или API/база не готовы.

## Безопасность

- Не загружай `.env`/настоящий токен в GitHub, не присылай его в переписку.
- Не отключай Telegram-подпись, чтобы обойти 401.
- Не отправляй полный `initData` в чаты или логи.
- Пользовательские цели и финансовые операции **пока не синхронизируются**: сначала получаем 200 на `/api/v1/me`.
